blossom B의 base : node v that is not matched to any other in blossom B
free blossom : base가 blossom 밖의 node와 연결 안 된 구조
matched blossom : base가 blossom 밖의 node와 match 됨
inner blossom = root에서 홀수 개 edge 거리 (outer는 짝수 개 거리)
-> free_node(=outer) - unmatched - inner - matched - outer - unmatched - free_node에서, lifting을 하면
-> free_node(=outer) - matched - inner - unmatched - outer - matched - free_node 구조 + 경로상의 blossom 해체.
alternating path = matched, not, matched, not 구조
augmenting path = void, matched, not, matched, .... matched, void 구조

grow step : inner blossom, outer blossom 각각 1개씩 추가 (blossom = node도 됨 주의), inner blossom은 무조건 matched blossom임 -> 다시 말해서 내가 연결한 path 새로운 node에서 시작해서 만든 path 따라가는 거 = 새로운 free 만나는 건 grow 단계에서 넘어간 거임
-> 이거 새 free node = root일 때 root-unmatched-inner.... 이 구조로 해서, 마지막에 전환
-> 아무 free node를 root로 해서, 기존 matching과 먼 곳에서 잡으면 기존과 아무 상관 없는 matching 만들어질 수 있음.

blossom step : odd cycle 되었기에 blossom으로 변환 -> 무조건 cycle 형성되도록 새로 잡은 좌표(base) = outer(blossom 밖과 matching 된 node)임. ->blossom이 되었기에 blossom 안의 몇 개의 inner가 outer로 취급되게 됨.

expand step : inner blossom을 1개 이상의 blossom으로 replace함 (blossom 형성(압축)은 outer에서, 확장은 inner 이유 새 node 잡으면 inner <-> outer가 되기 때문에 가능함) -> blossom의 base가 cycle 내부적으로 양쪽 모두 unmatched 상태가 자연스럽기에. expand 했을 때, cycle에서 선택하는 방향은, node에서 출발해서 destination까지의 경로가 자연스러워지도록 알아서 됨 -> 주의점은 자연스러워지기 전에 augmenting path 변화 있었고, 그러면서 기존의 inner/outer가 유지 안 될 수 있음

dual adjustment 간단한 설명으로, 현재 dual variable과 가장 근접한 dist 선택
-> 규칙으로 outer는 무조건 dual variable +=, inner는 무조건 -=을 해야 함.

argumenting path 상의 blossom은 lifting할 때 무조건 재조합하기에 사라짐
alternating path는 bfs 등으로 구현할 경우 arguementing path가 아닌 경로도 탐색했고, 그에 따라 그 경로에 없는 blossom은 해체 안 함.
